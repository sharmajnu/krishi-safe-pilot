# KRISHI-SAFE Pilot — Claude Code handoff package

This folder converts a claude.ai research-planning discussion into a working
Claude Code project. `CLAUDE.md` is the distilled memory of that discussion;
Claude Code reads it automatically at the start of every session.

## Quickstart (laptop, no GPU)

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q                                  # 34 tests
.venv/bin/python -m src.schema validate data/items.sample.jsonl
.venv/bin/python -m src.run_pilot --config config.yaml --backend dummy
.venv/bin/python -m src.extract  --run outputs/<run_id>
.venv/bin/python -m src.verifier --run outputs/<run_id>
.venv/bin/python -m src.score    outputs/<run_id>/
.venv/bin/python -m src.plots    outputs/<run_id>/
```

Each phase prints the next command. Outputs land in `outputs/<run_id>/`:
`generations.jsonl` (append-only), `extractions.jsonl` + `extraction_audit.jsonl`
(read every line at pilot scale), `verdicts.jsonl`, `report.md` with the
pre-registered decision, `summary.json`, `unsafe_vs_joules.png`.

Status: pipeline implemented and green end-to-end in dummy mode, and the real
item set is BUILT: `data/items.jsonl` — 50 questions x 4 languages (EN/HI/TE/TA),
200 items, generated by `src/build_items.py` from `data/sources/facts.json`.
Every fact was collected 2026-08-16 from fetched official sources (PPQS
banned/restricted list updated 31.07.2026; CIB&RC Major Uses of Pesticides as
on 31.03.2026; Insecticides Rules 1971; FSSAI CTR Regulations 2011 via India
Code; TNAU agritech portal; ANGRAU RARS Tirupati PoPs) with verbatim spans;
source snapshots live in `data/corpus/` (also the RAG corpus) and the registry
in `data/registry.json`.

Remaining before a GPU run:
1. **Human verification** (the pilot spec assigns this to you, ~1-2 min/item):
   check each answer key against its snapshot/source, then flip `verify` to
   false. Spot-check the machine-drafted HI/TE/TA translations and flip
   `translation_verified` where good. Caveats to check are listed in
   `data/sources/facts.json` `_caveats` (notably: ANGRAU PoP is the 2014-15
   edition; no 2024-2026 gazette orders found — re-search before freezing F).
2. Run on a GPU: set `backend: vllm` (`pip install vllm pynvml`).

## How to start

```bash
# on your machine / lab server
cd krishi-safe-pilot
claude
```

Then paste this as the first prompt:

> Read CLAUDE.md and docs/pilot_spec.md fully. Then implement Phase 1 of the
> phase plan (schema + sample items + validation CLI). Ask me one question
> first: which L3 language (Telugu or Marathi) — then proceed. Do not start
> later phases until Phase 1 tests pass.

Work phase by phase. Good follow-up prompts per phase:

- Phase 2: "Implement src/energy.py per CLAUDE.md. Include a dummy mode and a
  __main__ self-test that runs without a GPU."
- Phase 5: "Implement the run loop. Then run the full pipeline end-to-end with
  --backend dummy and show me the generations.jsonl schema."
- Phase 7: "Write the verifier with pytest cases BEFORE the implementation
  (TDD): one passing and one failing case per rule type."
- Phase 8: "Run scoring on the dummy run and print the decision-rule table
  exactly as specified in CLAUDE.md."

## What's in here

- `CLAUDE.md` — project memory: thesis, decision rules, conventions, phase plan
- `docs/proposal.md` — full research proposal (markdown, Claude Code-readable)
- `docs/pilot_spec.md` — pilot design: strata, item templates, models, scoring
- `docs/*.docx` — the same two documents as Word files for circulation
- `THRESHOLD_CHANGES.md` — append-only log of scope/threshold changes

## Ground rules baked into CLAUDE.md

- Dummy backend first: the whole pipeline must run on a laptop with no GPU
  before you spend lab-server time.
- Regulatory facts are never invented; unverifiable items get dropped.
- Decision thresholds are pre-registered; changes go in THRESHOLD_CHANGES.md.
- Raw generations are append-only.

## On the lab server

Claude Code runs fine over SSH. Typical flow: sync this folder (git or scp),
`claude` in the repo, switch `--backend dummy` → `--backend vllm` in
config.yaml, and reserve the GPU exclusively during measured runs (power
readings are per-GPU, not per-process — shared jobs corrupt the energy data).
